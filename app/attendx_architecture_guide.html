How GoRouter redirects enforce guest route constraints and role-based access

GoRouter Route Guard Logic
Every route change triggers the declarative redirect logic in app_router.dart. 
flowchart LR
    Request[Route Request: state.matchedLocation] --> GuardCheck{Is User Logged In?\nAuthService.isLoggedIn}
    
    GuardCheck -->|NO| CheckGuest{Is requested path in _guestRoutes?\n/splash, /onboarding, /login, /signup}
    CheckGuest -->|YES| AllowGuest[Allow Navigation to Guest Screen]
    CheckGuest -->|NO| ForceSplash[Redirect to: /splash]

    GuardCheck -->|YES| CheckIfGuest{Is requested path in _guestRoutes?}

7. Start-to-End Page Walkthrough (All 8 Screens)

Exhaustive explanation of what each page renders, user actions, data flow, and transitions

1
Splash Screen /splash
Cold Start Entry

The initial greeting screen shown immediately when the Flutter engine completes initialization.

  • Visual Composition: Centered AttendX logo (school cap icon inside a rounded red square with soft red glow), 'AttendX' title in Inter 32px font, and a 'ERP Attendance System' badge pill.
  • Animation Mechanism: Driven by an AnimationController (750ms duration) with AppCurves.springBouncy cubic scaling and easeOut fade.
  • Auto-Transition: A non-blocking Timer fires at 1,400ms to navigate smoothly to /onboarding using context.go().
2
Onboarding Screen /onboarding
Product Introduction

A sleek 4-step carousel guiding new users through AttendX's capabilities.

  • Slide 1 - Fast Attendance: "Mark attendance in seconds" (faculty 1-tap roll calls).
  • Slide 2 - Student Visibility: "Track your attendance" (live subject percentages & standing).
  • Slide 3 - Management Oversight: "Insights for HODs and Admins" (department-wide reports & trends).
  • Slide 4 - Design Excellence: "Fast, clean and simple" (tactile Apple-grade fluidity).
  • Interactions: Swiping triggers animated pill width expansions (8px to 24px); tapping 'Skip' or 'Get Started' immediately routes to /login.
3
Login Screen /login
Authentication Gateway

The authentication hub featuring one-tap demo account switching for rapid evaluation.

  • Demo Account Selector Chips: 4 toggleable chips at the top of the form (Admin, HOD, Faculty, Student) that automatically populate email and password fields.
  • Form Validation: Checks for non-empty credentials and valid email formatting before invoking AuthService.login.
  • Role Routing: Upon successful credentials match, dynamically routes to /student, /faculty, /hod, or /admin.
  • Registration Link: Allows users without accounts to navigate to /signup.
4
Sign-Up Screen /signup
Account Registration

Permits registration of new in-memory user accounts for live demonstration.

  • Fields: Full Name, Email Address, Password, and Password Confirmation.
  • Role Picker: Interactive pill selector choosing whether the new user registers as a Student, Faculty, HOD, or Admin.
  • In-Memory Provisioning: AuthService.signUp() adds the user to the local runtime memory map and signs them in immediately.
5
Student Dashboard /student
Student Experience

A comprehensive portal for students to track attendance across subjects.

  • Tab 1 - Home: Circular overall percentage gauge (76.7%), total classes attended (188/245), 'At Risk' warning card if any subject is below 75%, and quick stats row.
  • Interactive Subject Sheet: Tapping any subject card opens a modal sheet displaying attendance breakdown, teacher name, and a dynamic simulator stating exactly how many more classes must be attended to achieve 75%.
  • Tab 2 - View (History): Chronological timeline of attendance sessions with filter chips (All, CS201, CS202, CS203, CS204, CS205) and colored status pills.
  • Tab 3 - Info: Student identity profile card (Rahul Student, Roll No: CS2022-001, Computer Science 3rd Year) and academic attendance guidelines.
6
Faculty Dashboard /faculty
Faculty Experience

The teacher's command center for conducting sessions and reviewing class performance.

  • Tab 1 - Home: Daily greeting banner, quick action buttons ('Mark Attendance', 'View Reports'), aggregate metrics, and list of assigned subjects (Data Structures CS201, Operating Systems CS205).
  • Sub-View - Mark Attendance: Selecting a subject launches the full-screen roll-call interface. Faculty can tap Present (green), Absent (red), or Late (amber) for each of the 8 students, or use the 'Mark All Present' shortcut button. Submitting attendance records the session with an Apple-style success confirmation.
  • Sub-View - Reports: Visual subject performance distribution, class averages, and list of defaulters needing academic intervention.
  • Tab 2 - View (Overview): Tabular subject summary showing total conducted sessions, student counts, and class averages.
  • Tab 3 - Info: Faculty profile for Dr. Priya Patel, department info, and institutional guidelines.

8. Modules & Functions Master Catalog

Exhaustive technical catalog of methods, signatures, and operational logic

Core Service & Controller Functions
Detailed programmatic signatures across authentication, navigation, and state calculations.
Class / Module Method / Getter Signature Return Type Operational Logic & Purpose
AuthService login(String email, String password) Future<Map<String, dynamic>> Normalizes email to lower case, validates against _demoUsers map, updates _demoMode=true and stores current profile. Returns success status and role.
AuthService signUp({fullName, email, password, role}) Future<Map<String, dynamic>> Checks duplicate email key in _demoUsers, writes new user record into memory, signs the user in immediately, and sets demo profile.
AuthService logout() Future<void> Resets _demoMode = false and clears _demoProfile = null to invalidate the active session.
AuthService routeForRole(String? role) String Maps a role constant to its route string (e.g. UserRole.student -> '/student'). Defaults to '/login' if unrecognized.
AppRouter _buildApplePage(context, state, child) Page<dynamic> Constructs a CustomTransitionPage combining an easeOutCubic slide (begin: Offset(0.06, 0.0), end: Offset.zero) with a fade transition over 320ms.
StudentMockData overallPercent double Computes overall attendance ratio across all enrolled subjects: (totalClassesAttended / totalClassesHeld) * 100.
StudentMockData belowRequirement List<StudentSubject> Filters enrolled subjects where subject.percent < 75.0 and sorts worst-first.
FacultySubject percentFor(StudentAttendance s) int Calculates a single student's attendance percentage for this course: (s.attendedCount * 100 / sessions).round().
FacultySubject averagePercent int Computes overall class attendance average: ((presentTotal + lateTotal) * 100 / (sessions * studentCount)).round().
HodMockData averageAttendance double Calculates department-wide average: (totalPresent / totalSessions) * 100.
AdminMockData totalUsers int Aggregates the sum of all enrolled students and active faculty: students.length + faculty.length.
